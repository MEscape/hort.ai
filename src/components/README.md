# Shared components (`@components`)

UI that more than one module uses. It is generic (no business owner, no domain concept) and never imports a module. Before adding a component, check this index; update it in the same change (`docs/conventions/adding-a-ui-component.md`).

## Layout

| Folder       | What belongs there                                                                          | Exists |
| ------------ | ------------------------------------------------------------------------------------------- | ------ |
| `ui/`        | Design-system primitives (shadcn: `npx shadcn add <name>`, configured in `components.json`) | yes    |
| `layout/`    | Page-level building blocks that hold no business content                                    | yes    |
| `shared/`    | Composites built from primitives (`gen component`): panels, pagination, forms controls      | yes    |
| `providers/` | React context providers wired once in a layout                                              | yes    |

Create a folder with its first component; do not add empty ones.

## Available

- `layout/layout-primitives.tsx`: the page frame. `PageShell` (window-high column, stacking context for the `WorldScene`), `PageHeader` (the banner with the logo) and `PageMain` (the one `<main>`; `panel` = a card in a reading-width column with room for Hort on its edge, `centered` = a lone panel such as an error). `AuthShell` and the `error.tsx` files compose them. Add a primitive here when a second screen needs it, not before.
- `providers/i18n-provider.tsx` (`I18nProvider`, server): loads the request locale's messages for the namespaces a subtree declares and hands them to the client provider.
- `providers/i18n-client-provider.tsx` (`I18nClientProvider`, client): the `next-intl` client provider; Client Components receive only the namespaces their subtree declared.

## Authentication UI building blocks

`RouteErrorPanel` and `NotFoundPanel` (`shared/`): the translated, theme-aware panels that every `error.tsx` and `not-found.tsx` renders (`docs/rules/nextjs.md`), using the `app.routeError.*` and `app.notFound.*` messages. They are used by the authentication and locale route boundaries.

## Conventions

- Files are kebab-case, one primary export per file, named exports.
- Components hold at most a little logic (`docs/rules/react.md`); state and effects live in a `use-*.ts` hook.
- Styling uses the design tokens in `src/app/globals.css` (`--hortai-*`) through Tailwind; no hard-coded colours.
- Text comes from translations; an icon-only control has an accessible name.

- `ui/`: token-styled shadcn `Button`, `Input`, `Label`, `Alert`, `Card`, `Skeleton`, `Select` (dropdown), `Switch`, `Checkbox` and `ToggleGroup` (pressable chips). Curated Lucide icons are exported by `ui/icons.tsx`.
- `brand/`: `HortaiLogo`, the five-mood owl companion `Hort`, and the decorative warm-paper landscape `WorldScene`. Hort references the canonical artwork in `public/brand/owl.svg`; `npm run brand:generate` exports matching icons and email assets. Interface colors come from semantic tokens; ambient motion respects calm mode and the OS preference. See [branding](../../docs/architecture/branding.md).
- `shared/`: `TextField` associates labels, hints and errors; `PasswordField` adds visibility and Caps Lock feedback; `FieldMessage` supplies consistent field feedback. `RouteErrorPanel` and `NotFoundPanel` provide translated recovery states.
- `shared/` also holds the single-card screen frame `HortPanel` (Hort on the edge, heading, content, footer), `SubmitButton`, and `FormAlert`; `brand/hort-mood.ts` (`hortMoodOf`) picks Hort's mood for a form.
- `shared/` also holds `SelectField` (a labelled shadcn `Select`; use it inside a `Controller`) and `ChoiceGroup` (a few big radio cards).
- `brand/character.tsx` (`Character`) draws a talking character (Max, Lili, Fina, ...) from a closed- and an open-mouth picture address; while `isSpeaking` the mouth alternates in an uneven rhythm (`src/hooks/use-lip-sync.ts`), stays open with reduced motion or calm mode, and a missing picture shows a paw (no background of its own, nothing under the character is painted: no ground shadow, no tint). The pictures are in the server-rendered page, so the browser fetches them before React runs (`use-picture-state.ts` watches each with `decode()`): the mouth stays shut and the face overlay waits until the pictures they belong to are loaded, so a swap or a late picture never blanks or floats. It knows nothing about the catalog: callers pass the addresses (the `tutors` module owns the catalog and the storage keys). `src/hooks/use-character-voice.ts` plays one stored audio file on request (play, stop, unavailable). Both are generic so every screen that shows a character reuses them.
- `brand/character-face.tsx` (`CharacterFaceOverlay`, with `character-face-eye.tsx`, `-layout.ts`, `-zzz.tsx`, `-types.ts`) animates a character's face on top of its flat pictures: pass `Character` an `expression` (`CharacterExpression`: `eyes` open/happy/sleepy, `lids` 0..1, `look`, `chewing`, `yawning`, `mouthOpen`, `slump`, `cool`) and a `face` (`CharacterFace`: measured eye shapes, pupils and fur colours of both pictures, kept with the tutors as `tutorFace(id)` and delivered as `TutorOption.face`). Lids are SVG shapes clipped to the eye-white and painted in the fur colour; only transforms animate, calm mode and reduced motion switch the transitions off, chewing stays shut and the "z"s stand still. Without `face` or `expression` it is just the picture. `src/hooks/use-character-expression.ts` (`useCharacterExpression({ boredomLevel, reaction })`) turns a boredom level 0..4 or a reaction (`pending`, `chew`, `happy`, `cheer`) into an expression, with blink / yawn / look-around timers that pause when the tab is hidden or the element is off-screen and do not exist in calm mode. A new picture of a character needs its face measured again.
- `shared/character-carousel.tsx` (`CharacterCarousel`, with `carousel-slide.tsx`, `slide-character.tsx` and `carousel-controls.tsx`) is a controlled stage of big characters where the centred one IS the selection: swipe or drag (pointer events), arrow keys / Home / End, the two big round buttons beside the active name (a pill with a tick), or a tap on a neighbour peeking at the side (a transparent tap area `neighbour-tap.tsx` over the outer fifth of the stage, at least 56px, outside the tab order and the accessibility tree; the stage bleeds to the screen edges so the neighbour shows); one `listbox` with `aria-activedescendant` and a polite "Max, 1 of 3, selected" status. The hero size is the CSS variable `--hero` (40% of the viewport height at most; override it with a class). Only transform and opacity animate (slide, bob and hop of the active one). The active one smiles with closed eyes for a moment after a choice and blinks (`face` from the catalog, `useCharacterExpression`); a neighbour shows only the star of its `badge`, the text is for a screen reader. Calm mode and `prefers-reduced-motion` drop the bob and hop and make the slide instant. Only the active character loads its open-mouth picture; every closed picture loads at once (there are few), so a character that becomes active is already there. It knows no catalog or namespace: callers pass `CarouselCharacter`s (id, name, pictures, optional `face`, optional text `badge`) and translated `labels`. The drag, the step logic, the hop and the smile live in `src/hooks/use-carousel-drag.ts` and `use-carousel.ts`.
- `shared/voice-preview.tsx` (`VoicePreview`, with `voice-play-button.tsx` and `voice-wave.tsx`) is a character you can listen to: a big picture you can tap (lip-synced through `Character`, smiling while it speaks), one huge round play / stop / "try again" button with a progress ring and sound bars on both sides, an optional `bubble` slot above, and a short status text only while loading or when the sound is unavailable (no file, no retry) or failed (retry), which hangs below the component out of the flow so no phase changes the page height; "speaking" is only read aloud. Nothing plays until it is pressed, only one sound plays at a time, and it stops when the address changes or the screen is left. The phases come from `src/hooks/use-voice-preview.ts` on top of `useCharacterVoice`.
- `src/hooks/use-calm-motion.ts` (`useCalmMotion`) is true when the OS asks for reduced motion or `data-motion="calm"` is set, and follows changes live; the lip sync, the carousel and the progression animations use it to fall back to a static picture. The companion avatar, level meter and daily reward card are not shared: they belong to the progression module (`@modules/progression/client`) because they know about XP and mood.
- `src/hooks/use-character-voice.ts` takes `{ trackProgress }` and also reports `progress` (0 to 1) and `isBuffering`; a sound that failed makes the status `unavailable` and the next press starts a fresh element. `useCalmMotion` (`use-calm-motion.ts`) says whether reduced motion or the in-app calm mode is on, for components that should leave motion out instead of only shortening it.
- `src/hooks/`: `usePasswordField`, `useCountdown`, `useFocusOnMount` and `useBeforeUnloadGuard` (unsaved-work guard for editors) hold reusable browser interaction state.
